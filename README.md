# CustomGento_AiImageLabel

EU AI Act labelling for Magento 2 product images. Mark an image as *AI generated* or *AI modified* in
the admin, and the storefront shows the official EU label icon on top of it, in any theme (Luma, Hyvä
or a custom one) and without touching a single theme file.

## Installation

```bash
composer require customgento/module-ai-image-label
bin/magento module:enable CustomGento_AiImageLabel
bin/magento setup:upgrade
```

Requires PHP 8.2 - 8.5 and Magento 2.4.

## Usage

Per image, open *Catalog > Products > (product) > Images And Videos*, click the image, and pick in the
*Image Detail* modal, right below *Role*:

- **AI labelling**: no AI / AI generated / AI modified
- **Label colour**: black or white, whichever reads better on that image

Save the product. That's all; there is nothing to configure.

## Where the icon shows

| Place | Icon |
| --- | --- |
| Product page gallery, main image and fullscreen | labelled icon ("AI generated" / "AI modified") |
| Product page gallery thumbnails | small AI mark |
| Category and search result pages, related / upsell / cross-sell, catalog widgets and sliders | small AI mark |
| Cart page and minicart | small AI mark |

The icon carries the explanation ("This image was fully generated by artificial intelligence...") as
`alt` and `title`, so screen readers announce it and hovering shows it. A German translation ships in
`i18n/de_DE.csv`.

## How it works without theme changes

**Server rendered images.** Every product image a theme renders in PHP goes through core's
`Magento\Catalog\Block\Product\ImageFactory`. `Plugin\AddAiBadgeToProductImagePlugin` looks up the
label there and wraps the theme's own image markup in `<span class="ai-image-label-wrapper">` with the
icon next to it. The theme's markup itself is left as it is.

**JavaScript rendered images.** The product gallery (Fotorama in Luma, Alpine in Hyvä) and the
minicart (Knockout in Luma, Alpine in Hyvä) are drawn in the browser. For those:

- `Plugin\AddAiLabelToGalleryJsonPlugin` prints an image url => icon map next to the gallery, as a
  `<script type="application/json" class="ai-image-label-data">` data block.
- `Plugin\AddAiLabelToConfigurableImagesPlugin` prints the same map for the child images of a
  configurable product, which the gallery switches to when an option or swatch is picked.
- `Plugin\AddAiLabelToCartItemDataPlugin` adds an `ai_image_label` entry to each item of the `cart`
  customer data section.
- `Plugin\AddAiLabelToSwatchMediaPlugin` adds an `ai_image_label` map to the `swatches/ajax/media`
  response, which both Luma and Hyvä fetch when a swatch is picked on a category or search page, to
  swap the tile image to the child's. On a page filtered by a swatch attribute in layered navigation,
  where the tile shows the matching child's image right away, `Plugin\AddAiLabelToListingSwatchesPlugin`
  prints those labels as a data block next to the swatches.
- `view/frontend/web/js/ai-image-label.js`, plain JavaScript without RequireJS or Alpine, puts the
  icon next to every `<img>` whose `src` is in any of these lists, and moves or removes it when the
  theme swaps an image. A server rendered icon is hidden while its image is swapped out, e.g. by a
  listing swatch, and shown again when the image comes back. Core's gallery placeholder image (`.gallery-placeholder__image`) is skipped, since
  it only gets hidden once the gallery has loaded, so the icon appears with the gallery itself.
  Likewise, when a theme keeps its own server rendered copy of an image under the gallery, only the
  visible copy on top (later in the DOM) gets the icon, so it is never shown twice.

The CSS (`view/frontend/web/css/ai-image-label.css`) and the script are loaded by
`view/frontend/layout/default.xml`.

The gallery JSON items also carry `aiIcon`, `aiMark` and `aiAlt`, for a theme that prefers to render
the icon in its own gallery template. An icon already present next to an image is never drawn twice.

## Styling

The icon sits in the bottom-right corner, since themes usually put their own Sale / New labels top
left. To move or resize it, override these classes in your theme:

| Class | Used for |
| --- | --- |
| `.ai-image-label` | every icon; the default size, used in listings, the cart and minicart |
| `.ai-image-label--full` | gallery main image and fullscreen |
| `.ai-image-label--thumb` | gallery thumbnails |
| `.ai-image-label-wrapper` | wrapper around server rendered images |
| `.ai-image-label-host` | set by the script on a statically positioned parent, so the icon can be positioned |

The heights are the visible icon height (see *The icons* below).

## The icons

`view/frontend/web/images/ai/*.svg` hold the official EU icons (*Icons for labelling AI-generated
content*). The artwork is unchanged, but each `viewBox` is cropped to the artwork's bounds, since the
originals carry a wide empty margin. If the set is ever reissued, replace the files, crop them the same
way and keep the names, because they are built by `Model\LabelProvider::iconUrl()`:

| File | Used for |
| --- | --- |
| `ai-generated-black.svg` / `ai-generated-white.svg` | labelled "AI generated" icon |
| `ai-modified-black.svg` / `ai-modified-white.svg` | labelled "AI modified" icon |
| `ai-mark-black.svg` / `ai-mark-white.svg` | small AI mark |

## Limitations

- **JavaScript off:** the gallery and minicart show no icon. Listings and the cart page still do,
  since they are rendered in PHP.
- **Swatches on listing pages:** a swatch that swaps the image on a category or search page shows the
  icon of the parent's image, not the child's. The product page is covered.
- **Minicart cache:** the cart section is cached in the browser, so a label changed in the admin shows
  in the minicart once the section is reloaded (e.g. after the next add to cart).
- **Image urls rewritten in the browser:** a CDN or image service that changes the image url after
  Magento rendered it stops the gallery and minicart icon from matching.
- **Headless / PWA storefronts and GraphQL** are not covered.

## Code overview

| Part | Role |
| --- | --- |
| `Model/Source/AiContent`, `Model/Source/LabelColor` | the single definition of the stored values and their labels |
| `Model/ResourceModel/AiLabel` | owns the two columns on `catalog_product_entity_media_gallery`, every read and write |
| `Plugin\GalleryResourcePlugin` | loads the columns with the media gallery, copies them when a product is duplicated |
| `Plugin\SaveAiFlagsPlugin` | validates and saves the posted values, only for images of the saved product |
| `Model\LabelProvider` | label lookup (per product and file), icon urls, badge HTML and the url => icon map |
| `Observer\ChangeGalleryTemplateObserver` | swaps in the admin gallery template with the two fields |

### Template copied from core

The admin *Image Detail* modal has no extension point for extra fields, so
`view/adminhtml/templates/helper/gallery.phtml` is a copy of `Magento_ProductVideo`'s
`view/adminhtml/templates/helper/gallery.phtml` (module-product-video 100.4.9) with the two selects,
their hidden inputs and a small change handler added. On a Magento upgrade,
diff it against the original and port whatever changed. The frontend uses no copied templates.
